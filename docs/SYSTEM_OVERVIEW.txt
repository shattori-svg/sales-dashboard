Daily Sales Report (Hourly Sales by Department) — System Overview
================================================================================

1. PURPOSE
----------
Web application for viewing and analyzing daily sales data from LS-Central
"Daily Sales Report (Hourly Sales by Department)" Excel exports. Users can
upload one or more Excel/CSV files, then view store-level snapshots and
all-store rankings with tables and charts. Data is stored in SQLite or
Supabase so reports can be recalled by date without re-uploading.

2. MAIN FEATURES
----------------
• Input: Upload Excel/CSV files (.xlsx/.xls/.csv). Each file is parsed and stored by
  the BusinessDate in the data; the system assigns data to "Today", "Yesterday",
  or "Last Week" (same weekday) for comparison. DoD (Day over Day) and WoW
  (Week over Week) are shown when corresponding dates exist.

• Store snapshot (店別速報): For a selected date/store, view:
  - Hourly table: time slot, net sales, DoD/WoW,
    quantity sold, receipt count.
  - KPI cards: net sales, quantity sold, sales per hour, unit per transaction,
    average selling price, and (non-total department) share.
  - Department composition by time slot: table and stacked bar chart (share of
    net sales per department per slot).
  - Bar charts: hourly net sales and receipt count (with optional comparison).
  - Line charts: landing forecast (projected end-of-day totals) for net sales
    and receipt count.
  Users can filter by department and time range. UI supports ja/en/th and
  responsive mobile layout.

• All stores snapshot (全店速報):
  - Ranks stores in Thailand for the selected date and department.
  - Columns: rank, store name, net sales, quantity sold, receipt count, DoD, WoW.
  - Sort by net sales, quantity sold, receipt count, store name, DoD, or WoW.

• Settings and master maintenance:
  - Per-user preferences (store, department, language, currency).
  - User master maintenance (including preferred language/currency).
  - Store-specific business hours.

3. TECHNOLOGY
-------------
• Backend: Node.js (v18+), Express. Serves static files and REST APIs.
• Database: SQLite (better-sqlite3) or Supabase. Report JSON is saved by
  (store_id, business_date), with master/user tables for settings.
• Parsing: xlsx + CSV parser; derives BusinessDate, hourly totals, and
  per-department hourly data.
• Frontend: Plain HTML/CSS/JS; Chart.js for all graphs. No framework.
• File upload: Multer (memory storage), max 10 MB per file.
• Auth: Session-based local auth and optional Microsoft Entra ID login.

4. API ENDPOINTS
----------------
• GET  /health              — Health check (returns { ok: true }).
• GET  /api/auth/status     — Authentication status, role, and user preferences.
• PUT  /api/me/preferences  — Save current user preferences.
• GET  /api/stores          — Store master list.
• PUT  /api/stores          — Update store master list (admin).
• GET  /api/business-hours  — Get business hours by store.
• PUT  /api/business-hours  — Save business hours by store (admin).
• GET  /api/dates           — List stored business_date values.
• GET  /api/report          — Query: referenceDate, storeId. Returns
                              today/yesterday/lastWeek objects.
• POST /api/upload          — Multipart form with "files" (multiple). Parses
                              Excel, saves by BusinessDate, returns saved
                              report set and updated date list.
                              Note: currently allowed without authentication.
• GET  /api/users           — User master list (admin).
• POST /api/users           — Create user (admin).
• PUT  /api/users/:id       — Update user (admin).
• DELETE /api/users/:id     — Delete user (admin).

5. DATA FLOW
------------
• Upload: User selects Excel files → POST /api/upload → parse each file →
  saveReport(businessDate, data, storeId) → response includes saved dates.
• Store snapshot view: User selects output date/store → GET /api/report →
  client receives today/yesterday/lastWeek → tables and charts rendered from
  total and byDepartment hourly data.
• All stores snapshot view: Client fetches stores and combines report data for
  ranking table with sortable metrics including DoD/WoW.

6. DEPLOYMENT
-------------
• Port: Uses process.env.PORT (default 3333).
• The app can run on Render, Railway, Fly.io, or any Node host. See DEPLOY.md
  for steps. SQLite is under project data/ (or DATA_DIR); many PaaS use
  ephemeral disk unless a persistent volume and DATA_DIR are configured.

7. FILES (MAIN)
---------------
• server.js   — Express app, auth middleware, upload handler, API routes.
• db.js       — SQLite init, saveReport, getReport, getAvailableDates.
• parser.js   — Excel/CSV parsing, BusinessDate detection, hourly and department data.
• index.html  — Markup for store snapshot and all stores snapshot panels.
• app.js      — Client state, rendering (tables, Chart.js), API calls, tab logic.
• style.css   — Layout and styling.
• upload.html / upload.js — Setup page (upload, users, stores, business hours).
• DEPLOY.md   — Cloud deployment instructions.
• docs/       — LS-Central integration notes, this overview.
